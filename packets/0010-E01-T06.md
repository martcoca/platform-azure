## Context

While cutting `platform-gcp` over to the shared action, that session found a defect in its
own contract check and reported it. **This repository has the same defect**, confirmed:
every assertion in `scripts/check-ci-contract.sh` is a fixed-string match, and none is
anchored to a line.

A fixed-string `grep` is satisfied by a **comment**. A `guarded-plan.yml` whose guard step
has been deleted and replaced by a comment saying it used to be there **passes the contract
check**. The check reports the file is fine while nothing guards the plan.

That is not hypothetical. `platform-gcp` demonstrated both versions against the same
compromised file: the fixed-string check exited 0 and printed "CI contract passed"; the
anchored check exited 1 and said the required line "must be a real YAML line, not a mention
of one in a comment."

This matters more here than an ordinary bug, because the contract check is what stands
between a plan and an apply. A gate that a comment satisfies is not a gate.

## The fix, already designed

`../platform-gcp/scripts/check-ci-contract.sh` is the reference. Read it. The shape:

- **Structural assertions are anchored** with `^[[:space:]]*<regex>[[:space:]]*$`. A comment
  begins with `#` after its indent and cannot match.
- **The `uses:` pin scanner is anchored the same way**, so a commented-out
  `uses: …@main` no longer trips it.
- **Fixed-string matching is kept only where the assertion really is about text appearing
  anywhere** in the file, rather than about a line existing.

Copy that shape. Do not re-derive it, and do not "improve" it.

## Goal

Every structural assertion in this repository's contract check requires a real YAML line,
and a guard step replaced by a comment fails it.

## Boundary

**`scripts/check-ci-contract.sh` and its tests only.** Do not change any workflow, the
action pin, the denylist, or what is denied. If tightening the check reveals that a
workflow is *actually* non-conformant, **stop and report it** — that is a finding, not a
thing to quietly fix in the same change.

No cloud mutation of any kind.

## Done when

- Every assertion about a **line existing** is anchored so that a comment cannot satisfy it.
- Assertions that are genuinely about text appearing anywhere are left as they are, and the
  evidence says which are which and why.
- **A negative fixture exists**: a copy of the guarded-plan workflow with the guard step
  deleted and replaced by a comment mentioning it. The check must fail against it.
- The check still passes against the real, conformant workflows.
- The negative fixture is committed and exercised by CI, not run once by hand.

## Check

From the repository root, with no cloud authentication:

```bash
scripts/check-ci-contract.sh          # exits 0 against the real workflows
```

Then the demonstration, which is the packet:

1. **Run the check against the commented-out fixture.** Show it **fails**, and show the
   message says the line must be real rather than a mention in a comment.
2. **Run the pre-change check against the same fixture** — from git history is fine — and
   show it **passed**. The contrast is the finding; state it plainly.
3. Show the check still passes against the untouched real workflows.
4. Show the anchored `uses:` scanner rejecting a commented-out `uses: …@main`.

## Notes

If any assertion cannot be anchored because the thing it checks legitimately is not a line,
say which and why. An honest exception with a reason is fine; a silent one is the defect
this packet exists to remove.

Write `evidence/0010-E01-T06.md`.
